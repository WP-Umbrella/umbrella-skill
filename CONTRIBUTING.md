# Contributing

Thanks for helping maintain umbrella. This doc covers the dev workflow: how to edit, build, and validate changes before opening a PR.

## Repo structure

| Path | Purpose | Edit ? |
|---|---|---|
| `src/` | **Canonical source** of all skill content (readable markdown + assets) | **Yes** |
| `skills/` | **Generated** output loaded by Claude Code | **No** — regenerated by the build |
| `scripts/build.sh` | Regenerates `skills/` from `src/` | — |
| `.github/workflows/verify-build.yml` | CI check that `skills/` is in sync with `src/` | — |
| `.claude-plugin/` | Plugin manifest + marketplace entry | Yes, carefully |

**Golden rule:** never edit `skills/` by hand. Your changes will be overwritten at the next build, and the CI will reject the PR for drift.

## Make a change

```bash
# 1. Edit the readable source
$EDITOR src/skills/umbrella/workflows/...

# 2. Rebuild
./scripts/build.sh

# 3. Commit both trees together
git add src/ skills/
git commit -m "refine workflow for X"
```

If you forget step 2, the CI fails at PR time with a diff showing what you should have rebuilt.

## Current build status

`scripts/build.sh` today is a **pass-through copy** — it mirrors `src/` into `skills/` verbatim. Caveman-based markdown compression (~46% token reduction) is planned but not yet wired; see the `TODO` inside the script.

Practical implication: for now, `diff -r src/skills skills` returns empty. Once caveman is wired, `skills/` will contain compressed markdown and the two trees will diverge by design — but the CI check will still work (it runs the build in the pipeline and compares against what's committed).

## Testing checklist

Five levels, fastest first. **Minimum before PR = L1 + L2 + L4.**

### L1 — Build sanity (10 sec, every change)

```bash
./scripts/build.sh && ./scripts/build.sh && \
  diff -r src/skills skills && echo "✓ parity OK" && \
  if find src -name '*.original.md' | grep -q .; then \
    echo "✗ source polluted by caveman"; \
  else \
    echo "✓ src/ clean"; \
  fi
```

Checks:
- Build runs cleanly
- Is **idempotent** (running twice = same result)
- `src/` and `skills/` are consistent (parity = identical content in v0; will differ once caveman is wired)
- No `.original.md` debris polluting `src/`

### L2 — Manifest validation (5 sec, before every push)

```bash
claude plugin validate .
claude plugin validate .claude-plugin/plugin.json
```

Both must pass. If one fails, fix the manifest before pushing — a broken manifest breaks the install for every user.

### L3 — Drift detection (1 min, one-time, to understand the CI)

Proves the CI check actually catches a missed rebuild:

```bash
# Snapshot current state
git add skills/ && git stash

# Modify src/ without rebuilding
echo "DRIFT_MARKER" >> src/skills/umbrella/SKILL.md

# Rebuild — this updates skills/
./scripts/build.sh

# See what the CI would see
git diff skills/ | head

# Cleanup
git checkout src/ skills/
git stash pop 2>/dev/null || true
```

If `git diff skills/` shows `DRIFT_MARKER`, the CI works as intended: any src/ change without a matching skills/ regeneration will fail the pipeline.

*(Requires at least one commit of the current state to work — git needs a reference to compare against.)*

### L4 — Plugin runtime (5 min, every skill/workflow change)

```bash
claude --plugin-dir .
```

Then inside Claude Code:

1. **Auto-invocation** — *"list my WP Umbrella sites"* → the skill should load, Claude calls the API with curl, results presented as a compact table.
2. **Slash commands visible** — type `/umbrella` → `/umbrella:sites`, `/umbrella:health` and `/umbrella:work` should appear in the autocomplete.
3. **Execute a slash command** — `/umbrella:health` → fleet-wide dashboard.
4. **Safety rule check** — *"update plugins on site <staging_id>"* → Claude must **ask confirmation** before firing any POST. Do **not** confirm; just observe that the gate works.

### L5 — Real-change simulation (2 min, only for build pipeline changes)

```bash
# Edit a workflow
echo "## Test section" >> src/skills/umbrella/workflows/reporting/project-inventory.md

# Rebuild
./scripts/build.sh

# Confirm the change propagated to skills/
grep "Test section" skills/umbrella/workflows/reporting/project-inventory.md

# Revert
git checkout src/ && ./scripts/build.sh
```

Demonstrates the full edit→build→deploy loop works end-to-end.

## Wiring caveman (future work)

After wiring:
- L1 parity test will change meaning: `diff -r` will no longer be empty (compressed ≠ source). Replace with a content-integrity check (e.g., compare frontmatter, verify no structural corruption).
- Measure compression ratio on a few files to validate the approach before committing.
